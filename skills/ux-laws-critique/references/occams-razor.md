# Occam's Razor

Source concept: https://lawsofux.com/occams-razor/

## When to load

Load this reference when feature creep, dense layouts, redundant controls, competing flows, speculative edge cases, or overengineered experiences.

## Lens

When multiple designs solve the same problem equally well, favor the one with fewer assumptions and less unnecessary complexity.

## Look for in the design

- elements that do not support the user's current goal
- multiple paths that create the same outcome without a reason
- complex explanations compensating for a complex design

## Critique moves

- Identify which elements can be removed without reducing task success.
- Favor the simplest flow that preserves required capability and safeguards.
- Challenge assumptions: who needs this, when, and what breaks if it disappears?

## Watch-out

Do not confuse simple with simplistic; retain complexity that the task genuinely requires.

## Pairs well with

Tesler's Law, Hick's Law, Law of Pragnanz
