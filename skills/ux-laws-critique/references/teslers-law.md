# Tesler's Law

Source concept: https://lawsofux.com/teslers-law/

## When to load

Load this reference when complex domains, enterprise tools, workflows with regulations, configuration, advanced settings, data entry, or simplification debates.

## Lens

Some complexity is inherent; design decides whether the system absorbs it or pushes it onto the user.

## Look for in the design

- complexity shifted to users through manual work or confusing rules
- over-simplification that hides necessary distinctions
- designs built for ideal rational users rather than real behavior

## Critique moves

- Move unavoidable complexity into system defaults, automation, validation, or guided steps where possible.
- Expose complexity only when the user needs control or verification.
- Name which complexity is intrinsic and which is self-inflicted by the interface.

## Watch-out

Do not promise to remove complexity that the task or regulation requires; relocate or explain it.

## Pairs well with

Occam's Razor, Postel's Law, Cognitive Load
